# Jant 简介

> **Pre-1.0**：Jant 仍处于早期阶段。请预期会有粗糙边角、破坏性变更，以及仍在持续调整的文档。

Jant 是一个为单作者准备的小型博客系统。它支持 note、link、quote、thread 和 collection。发布体验更像发帖，而不是打开一个后台管理面板。

没有关注者。没有点赞。没有算法信息流。

名字来自 _Jantelagen_，一个北欧社会概念，大致可以理解为“别把自己看得太重，也别总想着把自己放在别人之上”。我一直很喜欢这个词，它很适合这样一个希望保持安静的产品。

## 为什么还要做一个博客系统

最诚实的答案也许是：因为我找不到自己真正想要的东西。

我总是反复遇到同一组缺口。下面这些，才是我真正动手做 Jant 的原因。

**可见性和推送不是一回事。** 大多数博客系统都把“已发布”和“已广播”当成同一个决定。你发一篇东西，它就会同时进入 RSS、订阅者的 feed 和时间线。我想要的是：一篇内容可以挂在站点上，有自己的 URL，可能属于某个 collection，也可能只是某个 thread 的延续，但它不必自动变成一次公告。Jant 把这件事拆开了。内容可以是公开的，但不出现在默认 feed 里。`Featured` 是默认 feed，而不是 `Latest`。`Hidden from Latest` 则用来处理那些应该公开存在、但不该被主动推送出去的内容。

听起来这像是一个很小的差异。如果你在意它，它就一点也不小。

**我希望发布体验是现代的。** 不是 WordPress，不是 Ghost，不是另一个填表单、点保存、再回到后台的 dashboard，而是更接近发帖。Threads 在体验上做对了一部分：写一句，再补一句，再修一句，整件事保持成一个连续序列。这本来就是我思考的方式。我一直不明白，为什么更多博客系统没有围绕这种形态来设计。所以，Jant 有 threads。

**我一直比大多数博客软件更喜欢 Tumblr。** 不是那家公司，而是那个产品直觉：note、link、quote 应该是一等公民格式。它们是三种不同的写作形态，不是同一个编辑器里的三种“变通做法”。对我来说，这三种已经覆盖了这些年绝大多数我想写的东西。我也许漏看了一些项目，但认真找过之后，我依然觉得这条路线上的开源替代品少得惊人。

所以我就做了我自己想用的那个系统。我不是在论证别的工具都错了。它只是更适合我的发布方式。

## 它怎么运行

Jant 主要有两种运行方式：

| 方式               | 适合谁                           | 默认组合                                  |
| ------------------ | -------------------------------- | ----------------------------------------- |
| Cloudflare Workers | 想用极低维护成本获得全球部署的人 | D1 + R2                                   |
| Docker / Node.js   | 想在自己的服务器上自托管的人     | SQLite 或 Postgres + S3（推荐）或本地媒体 |

Cloudflare Workers 是一等公民部署目标，因为它几乎可以让博客长期以极低成本运行。对个人站点来说，这件事比看上去更重要。

但 Jant 也不绑定在单一运行时上。如果你更愿意把它跑在自己的服务器上，也完全可以。SQLite、Postgres、Docker 都支持。

## Jant 有什么

- **三种帖子格式**：note、link、quote，它们都是真正的一等公民，不是变通方案
- **Threads**：当一个想法需要延续时，可以回帖给自己，而不必把一切都写成一篇长文
- **Collections**：按主题整理帖子，更像一组策展书架，而不是标签
- **富附件**：图片、视频、音频、代码块、文档都能进入同一条发布流
- **Ratings**：给书、电影、文章等内容打分，并把这份记录留在自己的站点上
- **主题和字型**：可以改变站点气质，而不必把 Jant 做成模板市场
- **RSS、归档页和搜索**：让站点真正可以被浏览
- **完整 API**：可以自动化发布、导入和维护，而不必被 UI 限制住
- **导出到 Hugo**：你可以随时带着内容离开

## 托管选项

如果可以的话，我仍然鼓励你先自托管。它并不复杂，也能让整体结构更简单。

但我也完全理解，有些人就是不想多处理哪怕一步部署流程。所以这里也有托管选项。

目前我会逐步开放，主要先给朋友，以及那些真的需要帮助、愿意直接写信给我的人。如果你属于这种情况，可以写到 `owen#jant.me`。这些邮件我会自己看，再按情况开通。

价格尽量保持简单：

| 项目             | 价格               |
| ---------------- | ------------------ |
| 一个站点         | $10.46/year        |
| 每增加一个站点   | $5/year            |
| 包含的媒体存储   | 10 GB shared       |
| 升级后的媒体存储 | 50 GB for $25/year |

这个基础价格不是随便定的。很多年前，我就在自己的博客里写过，我很喜欢 `.com` 域名的那个价格带：低到觉得亲切，高到又不是玩笑，有一种“好像占了点便宜”的感觉。后来 Cloudflare 开始按成本价提供 `.com` 注册，没有额外加价，这就自然成了 Jant 的定价锚点。

大多数人永远用不完那 10 GB 存储。但如果你真的需要更多，也有升级路径。
